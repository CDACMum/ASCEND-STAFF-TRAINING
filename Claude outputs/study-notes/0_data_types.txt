Information vs data · Structured and unstructured · Nominal, ordinal, discrete, continuous · Time-series and cross-sectional · Data quality · From data type to method

Every session so far (correlation, merge, charts, mean and SD, probability) starts from one question that is easy to skip: what kind of data is this column? The answer decides which chart is honest, which statistic is allowed, which test applies and which model can learn from it. This note is the map.

The examples come from the datasets shared with the class: the e-commerce orders (customer_master, product_catalog, order_items, ecommerce_sales_customer_analytics) and the sheets of CDAC_DataBook.xlsx (nominal, ordinal, poisson, mtcars, iris, faithful, ERPData). dataset_statistics.csv describes the full e-commerce data: 138,116 transactions, 46 columns, 24,911 customers, 1 Jan 2021 to 31 Dec 2025, revenue $177.1 M, profit $76.1 M, average order value $1,282.50, average rating 3.68, return rate 6.85%, cancellation rate 6.08%. The class file holds a sample of 1,155 orders, so counts differ from the full figures. Every runnable cell below uses a small table of real rows copied from that file, so you can check the answers by eye.

────────────────────────────────────────
🟢 1 · What is data? Data, information, knowledge
────────────────────────────────────────
Data is a recorded fact about something: a number, a word, a date, a click, a photo. On its own it says little.

Take one cell of the e-commerce file:
    net_sales = 421.19
That is data. It is a number with no context.

Add context and it becomes information:
    "Order ORD-979609, placed on 19 Dec 2024 by a Consumer customer, paid by Digital Wallet, had net sales of $421.19."

Combine thousands of such facts and you can look for a pattern, which becomes knowledge once it is tested. A pattern worth testing:
    "In the class sample, Buy Now Pay Later orders average $1,188 against $1,381 for Digital Wallet orders. Is that gap real or just sampling noise?"

If the test supports it, act on it and you have a decision:
    "Review the Buy Now Pay Later offer for high-value baskets."

The ladder is: DATA → INFORMATION → KNOWLEDGE → DECISION. Statistics and machine learning are the tools that climb it.

• A single value is a DATA POINT or observation.
• A column is a VARIABLE (also called feature, field, attribute).
• A row is a RECORD (also called observation, case, instance).
• A table of records is a DATASET.
• Data about data (units, definitions, source, date range) is METADATA. dataset_statistics.csv is metadata for the e-commerce file.

────────────────────────────────────────
🟢 2 · Why data matters: five jobs it does
────────────────────────────────────────
Organisations collect data because it lets them do five things, in rising order of value:
• DESCRIBE what happened: total revenue, average order value, return rate. (mean, median, counts, charts)
• DIAGNOSE why: why is the return rate 6.85%? Which category, supplier or delivery delay drives it? (groupby, correlation, tests)
• PREDICT what will happen: which customers will cancel, what next month's demand is. (regression, classification, forecasting)
• PRESCRIBE what to do: which discount maximises profit without hurting margin. (optimisation, experiments)
• AUTOMATE the decision: recommend a product, flag a fraud payment, set a delivery estimate, with no human in the loop.

Real-time examples you meet every day:
• A food or grocery app estimates your delivery time from distance, traffic, restaurant prep time and past orders. (continuous data in, a regression out)
• A bank flags a card payment as fraud in under a second from amount, place, time and history. (classification on streaming data)
• A streaming service ranks what to show you from what you watched and skipped. (behaviour data)
• A retailer reorders stock before it runs out from past demand by day and season. (time-series)
• A hospital screens patients for diabetes from glucose, blood pressure and age, which is the diabetes sheet in the DataBook. (mixed data types, binary outcome)
• A factory predicts a machine fault from sensor readings. (sensor stream)

Why quality matters as much as quantity: a model or a report is only as good as its data. "Garbage in, garbage out" is a rule, not a slogan. In this course you have already met the cost: an outlier pulling a mean (21 Oct), the wrong type of chart (17 Oct), and a merge that quietly dropped rows (16 Oct).

────────────────────────────────────────
🟢 3 · The first split: structured, semi-structured, unstructured
────────────────────────────────────────
• STRUCTURED: rows and columns with a fixed meaning. SQL tables, Excel sheets, CSV files. All the e-commerce files and the DataBook are structured. Most of this course works here.
• SEMI-STRUCTURED: has labels but no fixed table shape. JSON from an app, XML, web-server logs, a clickstream: {"user":"CUST-000001","event":"add_to_cart","product":"PROD-000738","time":"16:37:47"}. You usually flatten it into a table before analysis (pd.json_normalize).
• UNSTRUCTURED: no table shape at all. Images, audio, video, PDFs, free text. The customer_review column ("Satisfied with the purchase.") is unstructured text sitting inside a structured table. Text must be turned into numbers first, for example by counting words, or by using the review_sentiment label that the file already provides.

Rough share in the real world: most new data is unstructured, but most day-to-day analysis still starts from structured tables.

    Where each piece of the e-commerce data sits
    order_date, quantity, net_sales ...   → structured
    one order as a JSON event             → semi-structured
    customer_review text, product photos  → unstructured

🔵 4 · The main split for statistics: qualitative and quantitative
────────────────────────────────────────
Two families, four types.

QUALITATIVE (categorical): describes a quality or a group. Arithmetic on the values means nothing.
• NOMINAL: categories with NO order. customer_segment (Consumer, Premium, VIP, Business), payment_method, gender, region, warehouse, sales_channel, marketing_channel. Also the DataBook "prog" column (programme type 1, 2, 3).
• ORDINAL: categories WITH a natural order, but gaps between them are not equal or not known. review_sentiment (Negative < Neutral < Positive), delivery_status in the sense on time < delayed, a size S/M/L/XL, a rank (Prof, AssocProf, AsstProf in the salaries sheet), a satisfaction scale 1 to 5 treated as labels, "ses" (low, middle, high) in the nominal sheet.

QUANTITATIVE (numeric): a measured or counted amount. Arithmetic works.
• DISCRETE: counted, whole numbers, gaps between possible values. quantity (items in an order), loyalty_points_earned, customer_order_count, num_awards (poisson sheet), daysabs (neg_bin sheet), number of cylinders in mtcars.
• CONTINUOUS: measured, any value in a range, with decimals. net_sales, profit, unit_price, delivery_days measured to the hour, customer_age measured exactly, eruptions and waiting in the faithful sheet, mpg and weight in mtcars.

Sub-split of numeric data, sometimes asked in interviews:
• INTERVAL: equal gaps, but zero is arbitrary and ratios do not make sense. Temperature in °C (20°C is not "twice as hot" as 10°C), calendar year, clock time.
• RATIO: equal gaps AND a true zero, so ratios make sense. net_sales (a $200 order is twice a $100 order), age, weight, delivery days, count of items.

Four quick questions that classify any column:
1. Is it a number you can add and the result means something? No → qualitative (go to 2). Yes → quantitative (go to 3).
2. Do the categories have an order? Yes → ordinal. No → nominal.
3. Is it counted in whole units, or measured on a scale? Counted → discrete. Measured → continuous.
4. Is zero a true "none"? Yes → ratio. No → interval.

🔵 5 · Traps: columns that fool you
────────────────────────────────────────
• NUMBERS THAT ARE LABELS. customer_postal_code is stored as an integer, but a mean postal code is meaningless. The same goes for customer_id, order numbers, phone numbers and the DataBook codes ses = 1, 2, 3 and prog = 1, 2, 3. Rule: if adding two values makes no sense, it is a label, so treat it as categorical. In pandas, store it as a string or category.
• RATINGS. A 1 to 5 star rating is ordinal: the gap between 4 and 5 stars is not guaranteed equal to the gap between 1 and 2. Averages of ratings (the 3.68 in dataset_statistics) are widely used and fine for a headline, but a median and a frequency table are safer, and a test for ordinal data (Mann-Whitney, Spearman) is the strict choice.
• AGE. Truly continuous, but recorded in whole years, so it looks discrete. Look at what the quantity IS, not how it was written.
• COUNTS ARE NOT CONTINUOUS. num_awards and daysabs are counts. They cannot be negative or fractional, and they are usually skewed, so they follow Poisson-type models, not the normal curve. This is why the DataBook has poisson and neg_bin sheets.
• DATES. order_date is a point on a timeline. You can subtract two dates to get a duration, but it is not a measured amount you average. Convert to a datetime type, then extract year, month, weekday.
• BINARY VARIABLES. is_repeat_customer (True/False), Outcome in the diabetes sheet (0/1), vs and am in mtcars. A two-category nominal variable. Coding 0/1 lets you calculate a proportion as a mean, and is what logistic regression predicts.
• DERIVED COLUMNS. profit_margin_percentage = profit / net_sales is a ratio computed from other columns, and customer_lifetime_value is a prediction. Know which columns are raw measurements and which are calculated.
• TARGET vs FEATURES. In modelling, the column you want to predict (response, label) is the target; the rest are features (predictors). What you can use depends on type: a continuous target gets regression, a categorical target gets classification.

────────────────────────────────────────
🔵 6 · What you may do with each type
────────────────────────────────────────
The type decides the summary, the chart and the test. This is the table behind the 17 and 21 Oct sessions.

    Type         Summary                       Chart                         Typical test / model
    Nominal      counts, proportions, mode     bar chart, pie chart          chi-square, logistic (as target)
    Ordinal      median, percentiles, counts   ordered bar chart, box plot   Mann-Whitney, Spearman
    Discrete     counts, mean, variance        bar chart, histogram          Poisson / binomial models
    Continuous   mean, median, SD, IQR         histogram, box plot, scatter  t-test, z-test, correlation, regression

Two categories together: nominal × nominal → crosstab + chi-square. Continuous × continuous → scatter + Pearson correlation. Continuous × nominal → box plot per group + t-test or ANOVA. Nominal target from continuous features → logistic regression, KNN.

Examples from the class files:
• payment_method × order_status (nominal × nominal): crosstab and chi-square, exactly as in the diabetes DietType × Outcome example on 8 Oct.
• yrs_service × salary (continuous × continuous): scatter and pearsonr, as on 7 Oct.
• gender × salary (nominal × continuous): box plot and a two-sample test, as on 7 Oct.
• Material × Location counts (nominal × nominal): a grouped or stacked bar chart, as on 17 Oct.

🔵 7 · Other ways data is described
────────────────────────────────────────
Type is one axis. Real datasets also differ on these:

BY TIME
• CROSS-SECTIONAL: many subjects at one moment. The customer_master table (11,959 customers, one row each) is a snapshot.
• TIME-SERIES: one subject measured repeatedly over time. Monthly revenue 2021 to 2025, birth-rate readings in the DataBook "birth" sheet. Order matters, so never shuffle it before modelling.
• PANEL (longitudinal): many subjects, each over time. Each customer's orders across five years. The Health sheet (Country × Disease × Year) is panel data, which is why melt and pivot were needed on 17 Oct.

BY SOURCE
• PRIMARY: you collected it yourself (a customer survey, an experiment).
• SECONDARY: someone else collected it (a public dataset, the faculty file).
• OBSERVATIONAL: recorded as it happened (orders). Shows association.
• EXPERIMENTAL: you changed something on purpose and compared (an A/B test of two checkout pages). The only kind that can prove cause.

BY SPEED
• BATCH: collected, stored, analysed later (a monthly sales report).
• STREAMING / REAL-TIME: arrives continuously and is used within seconds (card-fraud scoring, live delivery tracking, sensor monitoring).

BY SIZE (the 3 Vs, later 5): VOLUME (how much), VELOCITY (how fast it arrives), VARIETY (how many formats). The full e-commerce data, 138,116 rows × 46 columns, is large for Excel but small for pandas. "Big data" begins when one machine can no longer hold or process it.

🔵 8 · Where the e-commerce tables fit together
────────────────────────────────────────
Four files, each at a different grain (what one row means):
• customer_master: one row per customer. Key: customer_id. Holds age, gender, segment, city, state, country, region, customer_acquisition_cost.
• product_catalog: one row per product. Key: product_id. Holds category, subcategory, brand, supplier, unit_price, product_cost, product_rating.
• order_items: one row per product line inside an order. Keys: order_id and product_id. Holds quantity, discount, gross_sales, tax, shipping, net_sales, cost and profit.
• ecommerce_sales_customer_analytics: one row per order, with customer and delivery details. Key: order_id.

Link them with merge on the key columns (16 Oct):
    orders.merge(customers, on="customer_id")
    items.merge(products, on="product_id")

Wrong grain is a classic mistake. If you total net_sales from the per-order table and from order_items without checking, you may double-count. Before any analysis, ask: what does ONE row represent, and what uniquely identifies it?

🟠 9 · Data types in pandas
────────────────────────────────────────
pandas stores columns as int64, float64, object/str, bool, datetime64 and category. It sees the storage, not the meaning, so you must set the right type yourself:
• Postal codes and IDs → string, not int.
• A nominal column with few values → "category" (smaller, faster, and groupby behaves).
• An ordinal column → ordered category, so comparisons and sorting follow the order.
• Dates → datetime, so you can use .dt.year, .dt.month, .dt.day_name().
• Money → float, never text. A "$1,282.50" string must be cleaned first.

    df["customer_postal_code"] = df["customer_postal_code"].astype(str)
    df["order_date"] = pd.to_datetime(df["order_date"])
    df["review_sentiment"] = df["review_sentiment"].astype(pd.CategoricalDtype(["Negative", "Neutral", "Positive"], ordered=True))
    df.info()          # one look at all dtypes and non-null counts

🟠 10 · Data quality: the five checks
────────────────────────────────────────
Before you trust any dataset, run these five checks (same ideas as the 5 Sep outlier note and the 16 Oct fillna session).

1. COMPLETENESS: how much is missing, and WHY?
   In the class e-commerce file, return_status is empty for 1,079 of 1,155 orders, and delivery_days, customer_rating and review_sentiment are empty for the same 206 orders. These are not random gaps. The 206 are exactly the Cancelled (79), Pending (51) and Returned (76) orders: nothing was delivered or reviewed in the usual way, so there is no delivery time and no review. And return_status is empty for every order that was NOT returned. This is STRUCTURAL missingness: the blank means "not applicable" or "none", not "lost". Filling it with the mean would be wrong. Ask the business meaning first.
2. UNIQUENESS: duplicates. order_id is unique here (1,155 distinct for 1,155 rows). If it were not, totals would be inflated.
3. VALIDITY: are values in range and in the allowed set? customer_age between 18 and 74 here. A rating of 7 on a 5-star scale, or a negative quantity, is invalid.
4. CONSISTENCY: the same thing written one way. "Digital Wallet" vs "digital wallet" vs "DigitalWallet" counts as three categories until you clean it. (Assignment 1 was built around exactly this.)
5. PLAUSIBILITY (outliers): extreme values that might be real or errors. Ten orders in the class file have NEGATIVE profit, which is real (a deep discount sold below cost), not an error. The IQR fences from 5 Sep and 19 Oct find such values; the business decides whether to keep them.

🟠 11 · Sampling in one page
────────────────────────────────────────
POPULATION = every unit you care about. SAMPLE = the subset you actually measured. The full e-commerce data has 138,116 transactions; the class file has 1,155 of them. A statistic from the sample (sample mean, x̄) estimates the matching population value (μ).
• A sample is only useful if it is REPRESENTATIVE. Random sampling gives every unit an equal chance.
• Bigger samples give steadier estimates (standard error = σ/√n).
• Bias beats size: 10,000 responses from only the website visitors who volunteered say little about all customers.
• This is why the formulas use n−1 for a sample variance (21 Oct) and why the central limit theorem (23 Oct) matters.

@run How close is a sample to the whole?
    import numpy as np

    rng = np.random.default_rng(2026)
    population = rng.lognormal(mean=6.6, sigma=0.9, size=138_116)     # skewed, like order values
    print("population: n = %d   mean = %.1f   median = %.1f" % (len(population), population.mean(), np.median(population)))

    for n in (30, 300, 1155, 10_000):
        means = [rng.choice(population, n).mean() for _ in range(500)]
        print("sample size %6d -> sample means range %7.1f to %7.1f   (spread %.1f)" % (n, min(means), max(means), np.std(means)))
    print()
    print("Bigger samples land closer to the population mean; the spread shrinks like 1/sqrt(n).")

🔴 12 · From data type to method: the decision map
────────────────────────────────────────
Use this when someone hands you a dataset and a question.

Step 1: What is the question's TARGET (what you want to explain or predict)?
Step 2: What TYPE is the target, and what type are the other columns?

    Target is...            Features are...            Start with
    continuous              continuous                 scatter, correlation, linear regression
    continuous              + a category               box plot per group, dummy variables, regression
    continuous              none (compare 2 groups)    two-sample t-test / z-test
    categorical (2 groups)  continuous / mixed         logistic regression, KNN
    categorical             categorical                crosstab, chi-square
    count (0,1,2,...)       any                        Poisson / negative-binomial
    none (no target)        any                        clustering, PCA, association rules

Mapped to the class sheets: salaries (continuous target, mixed features), diabetes (binary target, mixed features), nominal (categorical × categorical), poisson (count target), clusters and iris (no target / grouping), faithful (continuous × continuous).

Step 3: Check quality (section 10). Step 4: Pick the chart (section 6). Step 5: Run the test, then say what it means for the decision.

Exercises
────────────────────────────────────────
Classify each column (nominal / ordinal / discrete / continuous; ratio or interval for numbers).
1. warehouse (WH-001, WH-002 ...)
2. shipping_method (Standard, Express, Economy)
3. loyalty_points_earned
4. discount_amount
5. customer_postal_code
6. product_rating (e.g. 3.9)
7. temperature of a cold-storage room in °C
8. "ToxicLevel" in the ordinal sheet (62.0, 46.0 ...)
9. "Survival" in the ordinal sheet, coded 1, 2, 3
10. num_awards in the poisson sheet

Answers
1. Nominal (a label, even though it contains digits).
2. Nominal. Express and Economy differ in speed, but the column is a label, so ordinal only if you define an order by speed or price.
3. Discrete, ratio (counted points, true zero).
4. Continuous, ratio.
5. Nominal (label stored as an integer).
6. A measured score on a 1 to 5 scale: ordinal in the strict sense, treated as continuous when averaged.
7. Continuous, interval (0°C is not "no temperature").
8. Continuous, ratio (a measured concentration). The sheet's name "ordinal" refers to the Survival column, not this one.
9. Ordinal (the codes stand for ordered survival categories; the numbers are labels).
10. Discrete (a count), ratio.

────────────────────────────────────────
• For every column I know the meaning type, not only the pandas dtype.
• I have separated labels that look like numbers (IDs, postal codes, codes) from real measurements.
• I know what one row represents (the grain) and which column is the key.
• I have checked the five quality points: missing (and why), duplicates, validity, consistency, outliers.
• I picked the summary, the chart and the test from the data type.
• I know whether my data is a sample or the whole population, and whether it is representative.

Cheat sheet
────────────────────────────────────────
    Data → Information → Knowledge → Decision
    Qualitative: nominal (no order) · ordinal (ordered)
    Quantitative: discrete (counted) · continuous (measured)
    Interval = no true zero · Ratio = true zero
    Structured · semi-structured · unstructured
    Cross-sectional · time-series · panel
    Quality: complete? unique? valid? consistent? plausible?
    df.dtypes · df.info() · df.isna().sum() · df.duplicated() · astype("category")
